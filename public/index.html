Blast Radius Guard

A pre-execution policy gate between an AI agent and its tools — so an irreversible, high-blast-radius call can never run unreviewed.

The problem

In April 2026, a coding agent asked to clean up a staging volume scavenged an over-scoped API token from an unrelated file and issued a single volumeDelete against production. PocketOS's production database — and its co-located backups — were gone in nine seconds. No environment check, no confirmation step, no dry run. Blast Radius Guard is the checkpoint the agent cannot skip.

What the gate does

  • Credential check first — the caller's token must be valid, unexpired, and scoped to that tool. Expired or out-of-scope credentials are denied outright; broad standing tokens (scope: "*") are flagged on every call.
  • Every call scored before it runs — is it irreversible? Which environment does it target? What's the blast radius, 1–5?
  • Three decisions — allow, deny, or require_confirmation, with a human-readable dry run ("what would happen") for anything held. Held calls are not executed.
  • Tamper-evident audit — every evaluation is written to an append-only, SHA-256 hash-chained log; rewrite history and verification breaks.
